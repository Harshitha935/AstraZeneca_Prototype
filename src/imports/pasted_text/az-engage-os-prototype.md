Create a 7-frame interactive prototype that demonstrates AstraZeneca Spain's reinvented HCP engagement model as a living system. This is not an app prototype — it is a model prototype. Each frame shows the model responding to a signal. The visual language is AZ brand: deep magenta (#830051), clean white, navy (#1D2B4F), warm amber (#F5A623) as alert/activation color, light grey backgrounds for inactive states. Typography: sharp, clinical, intelligent. Product name: "AZ Engage OS."

FRAME 1 — Signal Entry: HCP Desktop
A realistic desktop screen. On the bottom right corner a small persistent chat widget is open — label "AZ Scientific Exchange." The HCP has typed: "What is the current dosing evidence for [treatment] in second-line NSCLC with co-mutations?" The message is sent. A subtle pulse animation begins on the chat widget border. A small tag appears under the message: "Query logged — classifying intent." This frame has one interaction: clicking the message or the pulse takes you to Frame 2. Bottom caption: "Every HCP interaction enters the system as a structured signal — not a data point, a semantic event."

FRAME 2 — The Graph Responds
Split screen. Left: the chat widget still visible with the query. Right: a knowledge graph expands into view — 8 nodes arranged organically: Scientific Evidence, Treatment Guidelines, Adverse Events, Unmet Clinical Need, Real-World Evidence, Product Information, Medical Affairs, Patient Outcomes. Three nodes light up in magenta: Scientific Evidence, Treatment Guidelines, Real-World Evidence. One node pulses amber: Unmet Clinical Need — with a small tooltip: "Repeated query type — pattern emerging." Routing indicator appears: an arrow pointing to Medical Affairs node with label "Flagged for MSL follow-up." Below the graph a log entry appears in real time like a terminal: "Query type: off-label scientific information request / Nodes activated: 3 / Unmet need signal: positive / Routed to: Medical Affairs Oncology." One interaction: a button "See how this escalates →" goes to Frame 3. Caption: "The model doesn't store a visit. It encodes what the interaction means and where it should go."

FRAME 3 — Escalation: Talk to Medical Affairs
Back to the chat widget, now on a phone screen — same conversation, channel has changed, loop has not. A button in the chat: "Talk to Medical Affairs." HCP taps it. A clean voice interface opens: three options at top as chips — "Report Adverse Event / Request Scientific Information / Product Quality." The HCP has selected "Request Scientific Information." A waveform shows they are speaking. Below: auto-transcribed text appears in real time. A "Submit to Medical Affairs — Oncology Team" button is ready. Small note: "Routed to the same knowledge graph. The channel changed. The signal didn't." One interaction: tapping Submit goes to Frame 4. Caption: "Compliance-safe. Voice-to-structured-submission. No form. No friction. No lost signal."

FRAME 4 — The Graph Accumulates
Full screen knowledge graph — now aggregate, not one query. Same 8 nodes but now weighted by volume and recency. Node sizes vary. Medical Affairs is large and magenta — high volume. Unmet Clinical Need is amber and pulsing — growing. Adverse Events node has a red ring: "High inbound volume — low resolution rate — 3 downstream nodes affected." A dependency chain is visible: Adverse Events → Real-World Evidence → Patient Outcomes, all slightly dimmed. A side panel shows: "This pattern has appeared across 47 interactions this quarter. Upstream dependency: Scientific Evidence content gap." One interaction: a button "See how MSLs feed this →" goes to Frame 5. Caption: "The graph doesn't just log. It shows what depends on what — and where the model is leaking."

FRAME 5 — MSL Agent Workflow
A workflow diagram view — not a chat, not a dashboard. Show an MSL in a meeting with an HCP (illustrated as two nodes connected). Above the MSL node: an agent chain diagram showing 3 AI agents in sequence — Agent 1: Query Classifier, Agent 2: Evidence Retriever, Agent 3: Response Synthesiser. Each agent has a small log: what it received, what it did, what it passed on. Between Agent 2 and Agent 3 a connection is highlighted amber: "Retrieved content does not match query classification — possible content gap." Below the workflow: the knowledge graph updates in real time — Scientific Evidence node decreases score slightly, Unmet Clinical Need node increases. A semantic case log appears: "Case type: off-label efficacy question / Agent responsible for gap: Evidence Retriever / Recommended action: content update or MSL briefing." One interaction: button "See patient signal →" goes to Frame 6. Caption: "The Loophole mechanic — applied at org level. Not which tool fired. Which node in the engagement model is responsible."

FRAME 6 — Patient Signal
A phone screen — a simple clean patient app. A patient has asked: "Why am I feeling fatigued in week 3 — is this normal with this treatment?" Below the query: the system shows it has been classified, anonymised, and attributed to a knowledge graph cluster. Zoom out: a graph of patient-reported themes shown as weighted clusters — Fatigue (largest), Treatment Sequencing Questions, Side Effect Timing, Emotional Wellbeing. A comparison panel appears: HCP graph on left (nodes: Dosing, Efficacy, Guidelines dominant), Patient graph on right (nodes: Side Effects, Recovery, Daily Impact dominant). A divergence indicator: "Gap detected: HCPs are not being asked about what patients are experiencing. This is a scientific exchange gap, not a data gap." One interaction: button "See what the model now knows →" goes to Frame 7. Caption: "Two graphs. Same treatment. Different realities. The model sees the gap neither side can see alone."
